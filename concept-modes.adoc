= Saiba mais sobre os modos de implantação do NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Você pode usar o NetApp Console por meio do aplicativo SaaS ou instalá-lo você mesmo em seu próprio ambiente (nuvem ou local).

NetApp refere-se a esses casos de uso como _modos de implantação_. Cada modo oferece diferentes conectividade, recursos e serviços para atender às suas necessidades de negócios e segurança.

Modo padrão (SaaS):: O aplicativo NetApp Console SaaS (software como serviço) permite o acesso a todos os serviços de dados NetApp, atualizações automáticas e opções flexíveis de autenticação, como federação de identidades e logins no site de suporte da NetApp. Este modo é compatível com assinaturas de marketplace e licenciamento BYOL. Este modo é ideal para a maioria dos usuários e organizações, especialmente aqueles que desejam os recursos e serviços mais completos disponíveis no NetApp Console.
Modo restrito (instalado em sua própria nuvem pública):: O modo restrito destina-se a organizações que necessitam de segurança reforçada e conectividade limitada, como governos e empresas regulamentadas. Você instala o NetApp Console em sua própria nuvem pública (em uma região governamental, soberana ou comercial), e ele possui conectividade de saída limitada aos endpoints da API do NetApp Console (hospedados no aplicativo SaaS). O modo restrito fornece acesso a serviços de dados essenciais, incluindo Cloud Volumes ONTAP, Azure NetApp Files, NetApp Backup and Recovery (em regiões governamentais e comerciais) e classificação de dados, além de atualizações de software automatizadas e federação de identidades.
Modo privado (instalado nas suas instalações ou na nuvem):: O modo privado destina-se a organizações com necessidades de segurança rigorosas, como as que utilizam AWS Secret Cloud, AWS Top Secret Cloud, Azure IL6 ou ambientes air-gapped. Ele não se conecta ao aplicativo SaaS do NetApp Console nem às APIs baseadas em nuvem do NetApp, proporcionando controle total e bloqueando a comunicação externa. Os serviços de dados suportados incluem NetApp Backup and Recovery, NetApp Data Classification, NetApp Replication e Cloud Volumes ONTAP. Todo o storage e autenticação permanecem locais, mantendo os dados dentro do seu ambiente. Utilize este modo para empresas contratadas da área de defesa, instituições financeiras com regras rígidas de residência de dados e agências governamentais com sistemas confidenciais.



NOTE: NetApp Console limita o fluxo de dados nos modos restrito e privado, mas você deve garantir que seu ambiente esteja em conformidade com seus regulamentos.

Cada modo de implantação difere em conectividade de saída, localização, instalação, autenticação, serviços de dados e métodos de cobrança.

O Console funciona da seguinte maneira no modo padrão:

Comunicação de saída:: É necessária conectividade de um agente com o aplicativo SaaS do Console, com os recursos publicamente disponíveis do seu provedor de nuvem e com outros componentes essenciais para as operações do dia a dia.
+
--
* link:task-install-agent-aws-console.html#networking-aws-agent["Endpoints que um agente contata na AWS"]
* link:task-install-agent-azure-console.html#networking-azure-agent["Pontos de extremidade que um agente contata no Azure"]
* link:task-install-agent-google-console-gcloud.html#networking-gcp-agent["Pontos de extremidade que um agente contata no Google Cloud"]


--
Localização compatível para um agente do Console:: No modo padrão, você pode instalar um agente Console na nuvem ou em suas instalações.



NOTE: A instalação de um agente na nuvem acarreta cobranças de uso da nuvem.

Atualizações do agente do console:: NetApp atualiza automaticamente o software do agente mensalmente.
Acesso à interface do usuário:: Você acessa a interface de usuário a partir do aplicativo Console SaaS, que está disponível na internet pública.
Ponto de extremidade da API:: As chamadas de API são feitas para o seguinte endpoint: \ https://api.bluexp.netapp.com
Autenticação:: NetApp Console oferece autenticação com auth0 ou logins do NetApp Support Site (NSS). A federação de identidades está disponível.

=== Como o NetApp Console funciona no modo restrito

O Console funciona da seguinte maneira no modo restrito:

Comunicação de saída:: Um agente requer conectividade de saída com as APIs baseadas em nuvem da NetApp para suporte a serviços de dados, atualizações de software, autenticação e transmissão de metadados.
+
--
NetApp não inicia comunicação com um agente. O agente inicia toda a comunicação e pode obter ou enviar dados das NetApp APIs e serviços conforme necessário.

Também é necessária uma conexão com recursos do provedor de nuvem dentro da região.

--
Localização com suporte para um agente:: No modo restrito, você instala agentes na nuvem: em uma região governamental, região soberana ou região comercial.
Atualizações do agente do console:: NetApp Console atualiza automaticamente o software do agente todos os meses.
Acesso à interface do usuário:: Os usuários acessam o Console a partir de uma máquina virtual de agente implantada em sua região de nuvem.
Ponto de extremidade da API:: As chamadas de API são feitas para uma máquina virtual de agente.
Autenticação:: A autenticação é fornecida através do serviço em nuvem do NetApp Console, utilizando o auth0. A federação de identidades também está disponível.




=== Como começar com o modo restrito

Você precisa habilitar o modo restrito ao criar sua conta do NetApp Console. Se você não tiver uma organização, será solicitado que crie uma e habilite o modo restrito ao fazer login pela primeira vez no agente do Console instalado.

Observe que a configuração do modo restrito é fixa após você criar a organização. Você não pode ativar ou desativar o modo restrito posteriormente. link:task-quick-start-restricted-mode.html["Aprenda como começar com o modo restrito"].

=== Como o NetApp Console funciona no modo privado

NetApp Console funciona da seguinte maneira no modo privado:

Comunicação de saída:: Não é necessária conectividade de saída com o aplicativo SaaS do Console (onde residem endpoints de API adicionais). Todos os pacotes, dependências e componentes essenciais são incluídos com o agente do Console e servidos a partir da máquina local. A conectividade com os recursos publicamente disponíveis do seu provedor de nuvem é necessária apenas se você estiver implantando Cloud Volumes ONTAP.
Localização compatível para o agente do Console:: No modo privado, o agente do Console é compatível com a nuvem ou no local.
Atualizações do agente do console:: Você deve atualizar manualmente o software do agente do Console. NetApp publica o software do agente do Console no site de suporte da NetApp em intervalos indefinidos.
Acesso à interface do usuário:: Os usuários acessam o Console a partir do agente do Console implantado em sua região de nuvem ou on-premises.
Ponto de extremidade da API:: As chamadas de API são feitas para a máquina virtual do agente do Console.
Autenticação:: A autenticação é feita por meio do gerenciamento e acesso de usuários locais. A autenticação não é fornecida pelo serviço em nuvem do NetApp Console.
