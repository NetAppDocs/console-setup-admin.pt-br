Você habilita os recursos do NetApp Console implantando agentes do Console, componentes de software leves que fornecem uma conexão segura entre seus sistemas de storage locais e de nuvem e o NetApp Console, permitindo orquestração avançada de storage e serviços de dados.



== O que faz um agente de Console

Um agente do Console cria uma ponte de rede entre seus sistemas de storage e o NetApp Console. Ele conecta sua infraestrutura com segurança às APIs da NetApp e ao Console, permitindo que você:

* Descubra e monitore sistemas de storage em ambientes AWS, Azure, Google Cloud e locais a partir do NetApp Console.
* Orquestre tarefas de provisionamento e configuração de storage em sistemas de storage a partir do NetApp Console.
* Habilite serviços avançados de proteção e otimização de dados.
* Associe as credenciais do seu provedor de nuvem a um agente do Console para rastrear com segurança o uso do serviço de nuvem e conectar as implantações à assinatura correta para faturamento preciso e gerenciamento de custos.




=== Arquitetura de agente

Os agentes operam com processos leves que:

* Extraia ou envie dados de e para o aplicativo SaaS Console (modos padrão e restrito) ou opere de forma puramente local (modo privado)
* Inicie toda a comunicação—o Console nunca inicia chamadas de saída para agentes
* Conecte-se aos seus sistemas de storage usando protocolos de gerenciamento padrão
* Use TLS 1.3 para comunicação segura com provedores de nuvem e as APIs do NetApp Console




=== Disponibilidade do agente e requisitos operacionais

Os agentes do Console são infraestrutura crítica para NetApp Console. NetApp Console pode lidar com interrupções curtas, mas os agentes devem permanecer operacionais e acessíveis para garantir a continuidade dos serviços de gerenciamento e dados. Você é responsável por assegurar:

* Os agentes continuam em funcionamento
* Os agentes possuem conectividade de rede com os endpoints necessários
* As falhas de infraestrutura são resolvidas rapidamente
* As VMs dos agentes são mantidas e atualizadas de acordo com as recomendações da NetApp




== Quando você precisar de um agente do NetApp Console

Você precisa implantar pelo menos um agente do Console quando quiser:

* Use modos de implantação restritos ou privados (Console instalado em seu próprio ambiente). Agentes adicionais são necessários para habilitar alguns serviços.
* Acesse serviços avançados de dados (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification e muito mais).
* Gerencie sistemas Cloud Volumes ONTAP.
* Execute tarefas avançadas de gerenciamento em clusters ONTAP locais.
* Acompanhe as licenças, monitore a integridade do storage e planeje upgrades do ciclo de vida.


Sem um agente, você pode realizar a descoberta básica de storage e acessar um conjunto limitado de recursos de monitoramento e gerenciamento de storage. No entanto, a maioria dos casos de uso corporativos exige um ou mais agentes operacionais.

link:concept-modes.html["Saiba mais sobre os modos de implantação do NetApp Console"] para entender quando você precisa de um agente e quais são as funcionalidades que os agentes possibilitam.



== Opções de implantação para agentes do Console

Você pode implantar agentes do Console em:

* Amazon Web Services (modos padrão, restrito ou privado)
* Microsoft Azure (modos padrão, restrito ou privado)
* Google Cloud (modos padrão, restrito ou privado)
* Nas suas instalações (modos padrão ou privado)


O modo de implantação do seu NetApp Console, ambiente de storage e necessidades de soberania de dados determinam onde você implanta os agentes. Implante vários agentes em diferentes ambientes para separação organizacional ou necessidades de negócios.

Após implantar um agente, você o registra na sua organização do NetApp Console para habilitar recursos para essa organização. Você pode associar vários sistemas de storage e serviços de dados a um único agente ou implantar vários agentes em ambientes diferentes para separação organizacional ou necessidades de negócios.



=== Agentes para o aplicativo SaaS NetApp Console (modo padrão)

Implante agentes na sua nuvem ou no local para estabelecer a conectividade com o aplicativo SaaS Console hospedado na nuvem. Os agentes habilitam recursos avançados enquanto a interface do usuário do Console permanece acessível de qualquer lugar.

Você pode instalar agentes diretamente do Console ao usar o aplicativo SaaS (modo padrão). Você pode instalar na AWS, Azure ou Google Cloud, ou manualmente em suas instalações, em seu próprio host Linux ou em seu ambiente vCenter.

Ao instalar um agente em suas instalações, você pode associar as credenciais do respectivo provedor de nuvem para habilitar a integração de faturamento e serviços de dados.



=== Agentes para NetApp Console em modo restrito

Você precisa instalar um agente a partir do qual os usuários acessarão o NetApp Console. Agentes adicionais são necessários para habilitar serviços de dados e gerenciar sistemas de storage.

Se você estiver usando o NetApp Console no modo restrito, você instala os agentes a partir do marketplace do seu provedor de nuvem ou instalando manualmente o software em seu próprio host Linux na nuvem, em suas instalações ou em seu ambiente VCenter.

Você precisará instalar um agente a partir do qual os usuários acessarão o NetApp Console. Agentes adicionais são necessários para habilitar os serviços de dados e gerenciar os sistemas de storage.

Ao instalar um agente em suas instalações, você pode associar as credenciais do respectivo provedor de nuvem para habilitar a integração de faturamento e serviços de dados.



=== Agentes para NetApp Console em modo privado (local ou na nuvem, sem conectividade de saída)

Você precisa instalar um agente a partir do qual os usuários acessarão o NetApp Console. Agentes adicionais são necessários para habilitar serviços de dados e gerenciar sistemas de storage.

Instale agentes em seu data center ou ambiente isolado da internet. Os agentes não têm conectividade com os endpoints da API da NetApp. Todas as operações permanecem locais, com total soberania de dados e controle.

Você precisará instalar um agente a partir do qual os usuários acessarão o NetApp Console. Agentes adicionais são necessários para habilitar os serviços de dados e gerenciar os sistemas de storage.

Ao instalar um agente em suas instalações, você pode associar as credenciais do respectivo provedor de nuvem para habilitar a integração de faturamento e serviços de dados.



=== Utilize vários agentes quando necessário

Cada agente opera de forma independente e pode gerenciar vários sistemas de storage e serviços de dados. Implante vários agentes quando precisar:

* Isolamento por tipo de storage ou função organizacional
* Atenda aos requisitos de segmentação geográfica ou de rede
