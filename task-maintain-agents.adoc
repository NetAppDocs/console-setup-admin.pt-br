= Manter as VMs do agente do NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Faça a manutenção das VMs do agente do NetApp Console aplicando atualizações de segurança do sistema operacional aos agentes instalados manualmente, respondendo a alertas de CPU, RAM e espaço em disco e redimensionando, parando e iniciando as VMs quando necessário.

Ao instalar manualmente um agente de Console, a manutenção do sistema operacional no host do agente é de sua responsabilidade (do cliente). Por exemplo, você (o cliente) deve aplicar as atualizações de segurança ao sistema operacional no host do agente seguindo os procedimentos padrão da sua empresa para distribuição de sistemas operacionais.

Se uma máquina virtual do agente ficar subprovisionada ou apresentar problemas de desempenho, você deve tomar as medidas apropriadas para atualizar os recursos da máquina virtual.


NOTE: Se você instalou o agente em vCenter, use a ferramenta de manutenção do Console para redimensionar a instância da VM. link:task-agent-vm-config.html["Aprenda como manter uma VM de agente no vCenter"^].



[[apply-operating-system-updates-to-the-manually-installed-agent-hosts]]
== Aplique atualizações do sistema operacional aos hosts do agente instalados manualmente

Aplique patches de segurança do sistema operacional sem interromper os serviços do host do agente.

Para manter a compatibilidade com as configurações suportadas, você deve impedir que o Docker ou o Podman sejam atualizados durante a aplicação de patches de rotina no sistema operacional. Você pode fazer isso excluindo temporariamente o Docker ou o Podman durante as atualizações ou configurando permanentemente o gerenciador de pacotes para ignorar as atualizações do Docker ou do Podman.

A seguir, apresentamos exemplos de como excluir atualizações do Docker ou do Podman em diferentes distribuições Linux. Consulte a documentação da sua distribuição Linux para obter as instruções mais recentes sobre como excluir pacotes das atualizações.

.Exemplo de Podman
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Exemplo de Docker
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resizing-the-vm-or-instance-type]]
== Redimensionar a VM ou o tipo de instância

Se você criar um agente do Console a partir do Console, ele implantará uma instância de VM no seu provedor de nuvem com uma configuração padrão.  Depois de criar o agente, não mude para uma instância de VM menor com menos CPU ou RAM.

Se você receber notificações de que sua VM do agente está com recursos insuficientes, considere atualizar para uma instância de VM maior, com mais CPU ou RAM, para garantir o desempenho ideal.


NOTE: Se você instalou o agente no VCenter, use a ferramenta de manutenção do Console para redimensionar a instância da VM. link:task-agent-vm-config.html["Aprenda a redimensionar a VM do agente no VCenter"^].

link:reference-agent-default-config.html["Saiba mais sobre a configuração padrão do agente"] .

Se você precisar aumentar a CPU ou a RAM da sua VM de agente, siga as instruções fornecidas pelo seu provedor de nuvem ou pela sua plataforma de virtualização local para redimensionar a instância da VM. NetApp recomenda dobrar a alocação atual de CPU e RAM para garantir o desempenho ideal. A tabela a seguir mostra os níveis de dimensionamento recomendados, em que cada nível dobra a CPU e a RAM do nível anterior.

[cols="1,1,1"]
|===
| Nível | CPU (núcleos ou vCPUs) | BATER 


| Mínimo | 8 | 32 GB 


| Médio | 16 | 64 GB 


| Grande | 32 | 128 GB 
|===

== Monitore o agente

O Console notifica você quando a VM do agente não está íntegra, incluindo problemas de espaço em disco, RAM e CPU.  Monitore essas notificações no Centro de Notificações do Console ou configure notificações por e-mail.  Aumentos ocasionais no espaço em disco, na memória ou no uso da CPU são normais, mas se isso acontecer com frequência, você deve tomar medidas para resolver.

Por exemplo, o Console notifica você quando um recurso do agente (CPU, RAM ou espaço em disco) excede 90% de sua capacidade total por 30 minutos consecutivos.  Depois, se o uso do recurso cair abaixo desse limite, a notificação será exibida como resolvida (verde) na Central de Notificações.


NOTE: Trabalhe com o suporte da NetApp se tiver dúvidas sobre como modificar sua máquina virtual do agente.

[[connect-to-the-linux-vm]]
[[connect-linux-host]]
== Conectar à VM Linux

Se você precisar se conectar à VM Linux na qual o agente é executado, use as opções de conectividade do seu provedor de nuvem.

AWS:: Ao criar a instância do agente na AWS, forneça uma chave de acesso e uma chave secreta da AWS.  Você pode usar esse par de chaves para fazer SSH na instância.  Use o nome de usuário 'ubuntu' para a instância do EC2 Linux.  Para agentes criados antes de maio de 2023, use o nome de usuário 'ec2-user'.
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["Documentação da AWS: Conecte-se à sua instância do Linux"^]

--
Azul:: Ao criar a VM do agente no Azure, você especifica um nome de usuário e escolhe autenticar com uma senha ou chave pública SSH.  Use o método de autenticação que você escolheu para se conectar à VM.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Documentação do Azure: SSH na sua VM"^]

--
Google Cloud:: Não é possível especificar um método de autenticação ao criar um agente no Google Cloud.  No entanto, você pode se conectar à instância da VM Linux usando o Google Cloud Console ou o Google Cloud CLI (gcloud).
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs: conectar-se a VMs Linux"^]
