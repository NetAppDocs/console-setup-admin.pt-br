[[apply-operating-system-updates-to-agent-hosts]]
== Aplique atualizações do sistema operacional aos hosts do agente

Aplique as atualizações de segurança ao sistema operacional e aos pacotes associados no host do agente para que o host permaneça seguro.

Essa é sua responsabilidade como cliente. O software do agente do Console pode se atualizar, mas não atualiza o sistema operacional nem os pacotes associados.


NOTE: Se você implantou o agente do Console no vCenter usando um OVA, o sistema operacional faz parte da imagem do agente. link:task-upgrade-agent.html#upgrade-a-vcenter-deployed-console-agent-using-an-iso["Atualize o agente usando uma ISO"^] para atualizar o sistema operacional.

Siga os procedimentos padrão da sua empresa para a distribuição do seu sistema operacional. Não é necessário interromper os serviços do host do agente ao aplicar patches de segurança do sistema operacional.

Em agentes que você não implantou a partir de um OVA, impeça que o Docker ou o Podman sejam atualizados durante a aplicação rotineira de patches do sistema operacional para manter a compatibilidade com as configurações suportadas. Você pode fazer isso excluindo temporariamente o Docker ou o Podman durante as atualizações ou configurando permanentemente o gerenciador de pacotes para ignorar as atualizações do Docker ou do Podman.

A seguir, apresentamos exemplos de como excluir atualizações do Docker ou do Podman em diferentes distribuições Linux. Consulte a documentação da sua distribuição Linux para obter as instruções mais recentes sobre como excluir pacotes das atualizações.

.Exemplo de Podman
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Exemplo de Docker
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resize-the-vm-or-instance-type]]
== Redimensionar a VM ou o tipo de instância

Aumente a CPU ou a RAM de uma máquina virtual de agente com recursos insuficientes para que o agente continue funcionando bem.

Se você criar um agente do Console no Console, ele implanta uma instância de VM no seu provedor de nuvem com uma configuração padrão. link:reference-agent-default-config.html["Saiba mais sobre as configurações padrão do agente"]. Depois de criar o agente, não mude para uma instância de VM menor com menos CPU ou RAM.

Se você receber notificações de que sua VM do agente está com recursos insuficientes, considere atualizar para uma instância de VM maior, com mais CPU ou RAM.


NOTE: Se você instalou o agente em vCenter, use a ferramenta de manutenção do Console para redimensionar a instância da VM. link:task-agent-vm-config.html["Aprenda como redimensionar a VM do agente no vCenter"^].

Se você precisar aumentar a CPU ou a RAM da sua VM de agente, siga as instruções fornecidas pelo seu provedor de nuvem ou pela sua plataforma de virtualização local para redimensionar a instância da VM. NetApp recomenda dobrar a alocação atual de CPU e RAM para garantir o desempenho ideal. A tabela a seguir mostra os níveis de dimensionamento recomendados, em que cada nível dobra a CPU e a RAM do nível anterior.

[cols="1,1,1"]
|===
| Nível | CPU (núcleos ou vCPUs) | BATER 


| Mínimo | 8 | 32 GB 


| Médio | 16 | 64 GB 


| Grande | 32 | 128 GB 
|===

== Monitore o agente

Mantenha-se informado sobre problemas de espaço de disco, RAM e CPU na sua máquina virtual do agente para que você possa resolvê-los.

O Console notifica você quando a VM do agente não está íntegra, incluindo problemas de espaço em disco, RAM e CPU.  Monitore essas notificações no Centro de Notificações do Console ou configure notificações por e-mail.  Aumentos ocasionais no espaço em disco, na memória ou no uso da CPU são normais, mas se isso acontecer com frequência, você deve tomar medidas para resolver.

Por exemplo, o Console notifica você quando um recurso do agente (CPU, RAM ou espaço em disco) excede 90% de sua capacidade total por 30 minutos consecutivos.  Depois, se o uso do recurso cair abaixo desse limite, a notificação será exibida como resolvida (verde) na Central de Notificações.


NOTE: Trabalhe com o suporte da NetApp se tiver dúvidas sobre como modificar sua máquina virtual do agente.

[[stop-and-start-the-agent-vm]]
== Pare e inicie a máquina virtual do agente

Limite o tempo de inatividade ao parar e iniciar a VM do agente, pois os serviços de gerenciamento e de dados dependem de o agente permanecer operacional.

Se necessário, pare e inicie a VM do agente usando o console do seu provedor de nuvem ou procedimentos locais padrão.

link:concept-agents.html#agents-must-be-operational-at-all-times["Esteja ciente de que o agente do Console deve estar operacional o tempo todo"] .



[[connect-to-the-linux-vm]]
[[connect-linux-host]]
== Conectar à VM Linux

Verifique o status do agente do Console em sua VM Linux para confirmar se ele está em execução.

Se você precisar se conectar à VM Linux na qual o agente é executado, use as opções de conectividade do seu provedor de nuvem.

AWS:: Ao criar a instância do agente na AWS, forneça uma chave de acesso e uma chave secreta da AWS.  Você pode usar esse par de chaves para fazer SSH na instância.  Use o nome de usuário 'ubuntu' para a instância do EC2 Linux.  Para agentes criados antes de maio de 2023, use o nome de usuário 'ec2-user'.
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["Documentação da AWS: Conecte-se à sua instância do Linux"^]

--
Azul:: Ao criar a VM do agente no Azure, você especifica um nome de usuário e escolhe autenticar com uma senha ou chave pública SSH.  Use o método de autenticação que você escolheu para se conectar à VM.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Documentação do Azure: SSH na sua VM"^]

--
Google Cloud:: Não é possível especificar um método de autenticação ao criar um agente no Google Cloud.  No entanto, você pode se conectar à instância da VM Linux usando o Google Cloud Console ou o Google Cloud CLI (gcloud).
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs: conectar-se a VMs Linux"^]
