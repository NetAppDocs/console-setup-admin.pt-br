= Saiba mais sobre os agentes do NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Um agente de console é um componente de software leve que você instala em sua rede para conectar sua infraestrutura de storage ao NetApp Console. Ele permite orquestração avançada de storage, serviços de dados e integração segura com a nuvem.



== O que faz um agente de Console

Um agente do Console preenche a lacuna de conectividade entre seus sistemas de armazenamento e NetApp Console. Ele conecta sua infraestrutura às NetApp APIs e ao Console de forma segura, permitindo que você:

* Descubra e monitore sistemas de storage em ambientes AWS, Azure, Google Cloud e locais a partir do NetApp Console.
* Orquestre tarefas de provisionamento e configuração de storage em sistemas de storage a partir do NetApp Console.
* Utilize fluxos de trabalho inteligentes para proteção e gerenciamento de dados.
* Monitore com segurança o uso de serviços em nuvem e conecte as implantações à assinatura correta para faturamento preciso e gerenciamento de custos.




=== Arquitetura do agente de console

Os agentes operam com processos leves que:

* Extrair ou enviar dados de e para o aplicativo SaaS NetApp Console (modos padrão e restrito)
* Inicie toda a comunicação—o Console nunca inicia chamadas de saída para agentes
* Conecte-se aos seus sistemas de storage usando protocolos de gerenciamento padrão
* Use TLS 1.3 para comunicação segura com provedores de nuvem e as APIs do NetApp Console




=== Requisitos operacionais e de disponibilidade do agente do console

Os agentes do Console são essenciais para o NetApp Console. Os agentes precisam permanecer operacionais e acessíveis para garantir a continuidade dos serviços de gerenciamento e dados. Você é responsável por assegurar:

* Os agentes continuam em funcionamento
* Os agentes possuem conectividade de rede com os endpoints necessários
* As falhas de infraestrutura são resolvidas rapidamente
* As VMs dos agentes são mantidas e atualizadas de acordo com as recomendações da NetApp




== Quando você precisar de um agente do NetApp Console

Você precisa implantar pelo menos um agente do Console quando quiser:

* Utilize modos de implantação restritos ou privados (Console instalado em seu próprio ambiente). Agentes adicionais podem ser necessários para habilitar alguns serviços.
* Acesse serviços avançados de dados (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification e muito mais).
* Gerencie sistemas Cloud Volumes ONTAP.
* Execute tarefas avançadas de gerenciamento em clusters ONTAP locais.
* Acompanhe as licenças, monitore a integridade do storage e planeje upgrades do ciclo de vida.


Sem um agente, você pode realizar a descoberta básica de storage e acessar um conjunto limitado de recursos de monitoramento e gerenciamento de storage. No entanto, a maioria dos casos de uso corporativos exige um ou mais agentes operacionais.

== Opções de implantação para agentes do Console

Você pode implantar agentes do Console em:

* Serviços Web da Amazon
* Microsoft Azure
* Google Cloud
+
Para gerenciar recursos do Google Cloud, implante seu agente no Google Cloud. Um agente local não pode gerenciar recursos do Google Cloud.

* Nas suas instalações (apenas modos standard ou privado)


O modo de implantação do seu NetApp Console, ambiente de storage e necessidades de soberania de dados determinam onde você implanta os agentes. Implante vários agentes em diferentes ambientes para separação organizacional ou necessidades de negócios.

Você pode implantar agentes diretamente do Console, do seu marketplace na nuvem ou manualmente no vCenter ou em suas instalações. link:concept-agent-install-options.html["Compare os métodos de implantação para escolher o mais adequado ao seu ambiente"].



=== Agentes para o aplicativo SaaS NetApp Console (modo padrão)

Implante agentes na sua nuvem ou no local para estabelecer a conectividade com o aplicativo SaaS Console hospedado na nuvem. Os agentes habilitam recursos avançados enquanto a interface do usuário do Console permanece acessível de qualquer lugar.

Você pode instalar agentes diretamente do Console ao usar o aplicativo SaaS (modo padrão). Você pode instalar na AWS, Azure ou Google Cloud, ou manualmente em suas instalações, em seu próprio host Linux ou em seu ambiente vCenter.



=== Agentes para NetApp Console em modo restrito

No modo restrito, os usuários acessam o NetApp Console diretamente de um agente instalado — não do aplicativo SaaS hospedado na nuvem. É necessário instalar pelo menos um agente para servir como ponto de acesso ao Console. Agentes adicionais são necessários para habilitar serviços de dados e gerenciar sistemas de storage.

Instale os agentes a partir do marketplace do seu provedor de nuvem ou instalando manualmente o software em seu próprio host Linux na nuvem, em suas instalações ou em seu ambiente VCenter.



=== Agentes para NetApp Console em modo privado (local ou na nuvem, sem conectividade de saída)

No modo privado, os usuários acessam o NetApp Console diretamente de um agente instalado. É necessário instalar pelo menos um agente para servir como ponto de acesso ao Console. Agentes adicionais são necessários para habilitar serviços de dados e gerenciar sistemas de armazenamento.

Instale agentes em seu data center ou ambiente isolado da internet. Os agentes não têm conectividade com os endpoints da API da NetApp, e todas as operações permanecem locais, com total soberania de dados e controle.



=== Utilize vários agentes quando necessário

Cada agente opera de forma independente e pode gerenciar vários sistemas de storage e serviços de dados. Implante vários agentes quando precisar:

* Isolamento por tipo de storage ou função organizacional
* Requisitos de segmentação geográfica ou de rede


Por exemplo:

* Em um ambiente multicloud, você pode implantar um agente na AWS e outro no Azure. Cada agente gerencia os sistemas Cloud Volumes ONTAP em seu respectivo ambiente.
* Um provedor de serviços pode usar uma organização do Console para fornecer serviços aos clientes e outra organização para recuperação de desastres de uma unidade de negócios. Cada organização precisa de seu próprio agente.




== Atualizações do agente do console

Os agentes na nuvem são atualizados automaticamente quando têm acesso à internet. Para agentes sem acesso à internet (modo privado), consulte link:task-upgrade-agent.html["Gerenciar atualizações do agente do console"] as instruções de atualização manual.
